## Windows sed 行尾符采用 CRLF

 使用 `winget install mbuilov.sed` 安装的 `(GNU sed) 4.9` 在输出时会采用 CRLF 作为行尾符，这非常不好。解决方法是 `sed -b` 以二进制形式处理文件

## Codex 按需加载 MCP

#AI

Codex 默认启用几个 MCP (node_repl, codex_apps)，我也有几个三方 MCP 需要加载（idalib-mcp），考虑到每次启动 Session 都会注入一段 MCP 的信息到 Context，处于节约 Token 的必要，也得把 MCP 摘出去。

一说是换成 SKILLS，但 IDA Pro MCP 这个有状态的服务不太好改为 cli，而且得本地启独立进程。好在了解到 subagent 可以单独设置运行 MCP

我就在安装 plugin 后写了个 agent 定义文件

```toml title="~/.codex/agents/ida-reverse-engineer.toml"
name = "ida-reverse-engineer"
description = "Specialist for IDA Pro-based reverse engineering..."
developer_instructions = """
You are the dedicated IDA Pro reverse-engineering specialist. Use the idalib-mcp tools for IDA database analysis and modern IDAPython only; prefer ida_* modules over legacy idc.
...
"""

[mcp_servers.idalib-mcp]
command = 'C:\\Users\\enihsyou\\.codex\\plugins\\cache\\mrexodia\\ida-pro-mcp\\0.1.0\\.venv\\Scripts\\idalib-mcp.exe'
args = ["--stdio"]
```

不过想要调用它，用 `@ida-reverse-engineer` 方式直接给 subagent 派任务

如果发现 subagent 工作的时候没有调用 idalib-mcp，而去尝试 objdump 等奇奇怪怪的路子，肯定是 MCP 没有激活。任何修改定义文件都需要重启 Codex，检查一下。

注意若是在 .codex/config.toml 中禁用 MCP 并在 subagent 定义中单独启用，这个想法是没用的 (v0.114.6）。更稳妥的是在 Subagent 中重复完整的 MCP 定义
- [skills.config enabled=false cannot be overridden by project or custom subagent config · 议题 #29846 · openai/codex](https://github.com/openai/codex/issues/29846)
