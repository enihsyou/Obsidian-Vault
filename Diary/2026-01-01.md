## VSCode & Zed 打开远程服务器根目录后持续占用 CPU

今天远程连接直接打开了根目录 (`/`），但远程设备的 CPU 占用居高不下。

VSCode 会有 rg 进程持续占用 CPU，进程命令行是：

```shell wrap
/root/.vscode-server/cli/servers/Stable-994fd12f8d3a5aa16f17d42c041e5809167e845a/server/node_modules/@vscode/ripgrep/bin/rg --files --hidden --case-sensitive --no-require-git -g !**/.git -g !**/.svn -g !**/.hg -g !**/.DS_Store -g !**/Thumbs.db -g !**/node_modules -g !**/bower_components -g !**/*.code-search --no-ignore-parent --follow --no-config --no-ignore-global
```

根据 [Search Issues · microsoft/vscode Wiki](https://github.com/microsoft/vscode/wiki/Search-Issues#slow-search-rg-running-for-a-long-time-or-consuming-lots-of-cpumemory) 的说明，关闭设置中 `"search.followSymlinks": false` 可解。

关闭后会提示这个是正常的可忽略。
	文件更改观察程序意外停止。重新加载窗口可能再次启用观察程序，除非无法监视工作区的文件更改。

---

相同的问题也出在 Zed 中，日志中有更详细的原因，在尝试访问 /proc 等无效路径

```json title=/root/.local/share/zed/logs/server-workspace-139.log wrap
{"level":1,"module_path":"worktree","file":"crates/worktree/src/worktree.rs","line":4322,"message":"(remote server) error reading target of symlink \"/proc/self/task/7961/fd/6\": canonicalizing \"/proc/self/task/7961/fd/6\": No such file or directory (os error 2)"}
```

- [Remote: Opening root ('/') triggers recursive loading/watching of all directories → high CPU load on server & client · Issue #39023 · zed-industries/zed](https://github.com/zed-industries/zed/issues/39023) 看上去正在修复中了

## 中国互联网产品强制登录两步验证

今天在登录天翼账号时有感而发，中国互联网产品沆瀣一气的登录验证手段，即码上加码，密码无用 + 强制扫码 + 短信验证码。

天翼账号还好给出了设备锁开关，腾讯云也有手段 [[2025-10-14#关闭腾讯云双因素身份验证]]，像知乎、豆瓣、京东就基本输完密码强制扫码。说好听叫强制两步验证，不好听叫强制找麻烦。PC 端应该用光一台 PC 就能完成的验证。

更可笑的是天翼账号密码强度验证限制规则里有这么一条，难道它的系统还有过通过密码实现 SQL 注入的历史？
- 密码长度为 9~16 个字符
- 包含数字、小写字母、大写字母、特殊字符 4 类
- **不能包含空格或（$-'"）4 种符号类型**
- 密码设置需避免键盘排序,如 123、jkl、asd 等键盘顺序

以及最近两年各家联合运营商推出的 _本机号码一键登录_ 功能，更是低效。在 Wi-Fi 下不能用，切换到流量在副卡下依然不能用，错误的手机号还可能单独再立刻注册个账号。
好在之前 [[需求应对网站#AdGuard Rules]] 规则中有相关条目，来自 [不想使用app中的本机号码一键登录，想使用传统的接收验证码来登录有什么方法可以解决？ - 知乎](https://www.zhihu.com/question/343994188/answer/2313669318)：
- 电信的认证服务域名是：`id6.me`
- 移动的认证服务域名是：`cmpassport.com`
