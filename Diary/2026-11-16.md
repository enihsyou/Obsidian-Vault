## WSL2 镜像网络产生大量 Hyper-V-VmSwitch 系统日志

#AIGC

系统日志 `Microsoft-Windows-Hyper-V-VmSwitch-Operational` 7 天积累了 25969 条（2026-11-09 20:08 到 11-16 15:52，约 3700 条/天）。通道上限 32 MiB 且 `retention: false`，旧记录会被环形覆盖。

来源是 `networkingMode=Mirrored`。WSL2 镜像网络用的是宿主机上的 FSE Switch（`fse.sys`），日志里 8342 条 ID 220 全部记在这个 switch 上，宿主常驻 `vSwitch (FSE Switch)` 和 `vEthernet (FSE HostVnic)` 两个适配器。

噪音分两部分：

- Event 285 每分钟一条（整点 `:37`），7 天 3336 条，内容是 `IOCTL_ENUM_NIC_COUNT_EX` 和 `OID_GEN_STATISTICS` "took too long to complete"。实际 `Execution time 0 ms`，期望耗时被算成 "<0 ms"，于是每次都判超时。属于遥测阈值算错，本身良性，但停不下来，WSL 发行版处于 Stopped 时照旧每分钟刷
- Event 220 / 0 / 143 是 WSL 工具 VM 每次启停产生的 NIC 连接断开、vDev Pause、VMBus 通道回调和 RSS 更新。7 天里出现 222 个不同的 VM 实例 GUID，约每天 32 次启停

处置：

```ini
# C:\Users\enihsyou\.wslconfig
[wsl2]
networkingMode=Consomme
vmIdleTimeout=600000
[general]
instanceIdleTimeout=150000
[experimental]
autoMemoryReclaim=Disabled
```

两个 idle timeout 调长而没有设成 `-1`，VM 仍会停，只是频率降下来。`autoMemoryReclaim=Disabled` 之后内存回收不再暂停 VM，ID 0 的 Pause 事件少一截。

网络模式需要 IPv6、host localhost、VPN 兼容和组播，这些是 Mirrored 提供的。当前 `.wslconfig` 写的是 `networkingMode=Consomme`，Consomme 不依赖 FSE Switch，这次那套 vSwitch 噪音按机制应该不会再出现，实际效果还没验证。

还没弄明白的是每天 32 次启停是谁触发的。没有管理员权限读不到 Hyper-V-Compute-Admin 和 HNS 日志，VS Code Remote WSL、终端和脚本都有可能。
