## VSCode 的 Agent / SKILL / Prompt

#AIGC

[Agent customization](https://code.visualstudio.com/docs/agents/concepts/customization) 中有几个概念 Custom Agent、Agent SKILLs、Prompt File 总是感觉互有重叠。

比较准确的理解是：它们不是简单的上下级关系，而是在 **Agent 执行过程的不同层次**发挥作用。

```text
                  User
                   │
                   │ /command
                   ▼
        ┌──────────────────────┐
        │     Prompt File      │  ← Invocation / 启动配置
        │                      │
        │ agent / model / tools│
        │ arguments / task     │
        └──────────┬───────────┘
                   │
                   ▼
        ┌──────────────────────┐
        │    Custom Agent      │  ← Execution Profile / 角色配置
        │                      │
        │ role / instructions  │
        │ default model/tools  │
        └──────────┬───────────┘
                   │
       ┌───────────┼──────────────┐
       ▼           ▼              ▼
 Instructions   Skills          Tools
       │           │              │
       │           │              ▼
       │           │             MCP
       │           │
       │           ▼
       │      按需加载的专业
       │      workflow/resources
       │
       ▼
  自动适用的项目/
  文件/编码规则
```

### 各自解决什么问题

|概念|核心作用|谁决定启用|
|---|---|---|
|**Prompt File**|一次任务的启动配置：选择 Agent、Model、Tools，并提供参数和任务说明|用户显式 `/command`|
|**Custom Agent**|可复用的执行角色：定义 persona、默认 instructions、model、tools|用户选择、Prompt 指定或 Agent 调度|
|**Skill**|可复用的专业能力、领域知识、SOP、脚本和资源|模型按相关性自动加载，或用户显式调用|
|**Instructions**|项目、文件或团队长期规则|自动应用|
|**Tool**|Agent 能执行的具体动作|模型在可用工具中选择|
|**MCP**|向 VS Code 提供外部工具/API|Tool 被 Agent 调用时|

VS Code 官方也把这些 customization 看作可组合的 building blocks，而不是互斥方案。
