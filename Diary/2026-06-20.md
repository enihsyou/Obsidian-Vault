## 为用户层级可执行程序添加文档和补全

已经使用 [[工具搜集/需求应对软件#^2c72d1|marcosnils/bin]] 管理用户可执行程序有段时间了，使用体验挺不错的。虽然有这些痛点
- 使用 GitHub API 拉取信息和下载资源，容易被限流。好在可以根据 [Bin Not Respecting GITHUB_AUTH_TOKEN · Issue #230 · marcosnils/bin](https://github.com/marcosnils/bin/issues/230) 设置 `GITHUB_AUTH_TOKEN` 绕过
- 只管理二进制，不处理文档和 Shell 补全，本次就是解决这个问题

我估计也是因为各个应用程序发布 Linux tar.gz 包时不一定会按照 deb / rpm 约定，在固定有规律的位置放置文档和补全，所以这个功能比较难实现。

但自己动手来也不是不行，主要是今天发现了有些工具会动态推导目录

- `manpath` 自动推导 `~/.local/share/man`
- `bash_completion` 自动推导 `~/.local/share/bash-completion/completions`

## Hermes Agent 提问会不等用户回复自行决定

就是在 Hermes Desktop 上发问时，因为提示声小，没听到，没处理，Agent 就自行做决策了。而且事后在 Desktop UI 上还看不到它问了什么，得去 Dashboard 看 History。

调研一番其实在配置文件中有一条 `agent.clarify_timeout` 可以控制，这个和 UI 中的审批超时设置还不一样。我直接改成 86400

## 在 Windows 上为 Chrome 开启 CDP 入口远程访问

最近想让 AI 操作浏览器，看到了大火的 [agent-browser | Browser Automation for AI](https://agent-browser.dev/)，想着给 Hermes 接上。开箱即用，但知乎的回答页面一直过不去，看 Dashboard 的 Network 页，感觉 Cookie 是不展示的。就打算在 Windows 上调试，发现 CDP 死活连不上。

- [agent-browser --auto-connect fails when Chrome remote debugging checkbox is disabled · 议题 #1003 · vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser/issues/1003)
- [Auto-launch failed: No running Chrome instance found. Launch Chrome with --remote-debugging-port or use --cdp · 议题 #1260 · vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser/issues/1260)
- [Bug: --cdp flag ignored, still triggers auto-launch on Windows · 议题 #1421 · vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser/issues/1421)

最终当前 v0.28.0 在 Windows 上的解决方案是命令行上用 `chrome --remote-debugging-port=9222` ，然后在 `chrome://inspect/#remote-debugging` 中勾上 `Allow remote debugging for this browser instance`。

很奇怪在 Linux 上的实例就不需要第二步。

## Chrome 导出包含 Cookie 的 HAR

刚才 [[#在 Windows 上为 Chrome 开启 CDP 入口远程访问]] 发现 Cookie 是不展示的，原因是 Chrome 默认在导出的 HAR 中清理敏感内容。想要保留得去 DevTools 的控制台，打开 `偏好设置 > 网络 > 允许生成包含敏感数据的 HAR`

- [网络功能参考  |  Chrome DevTools  |  Chrome for Developers](https://developer.chrome.com/docs/devtools/network/reference?hl=zh-cn#save-as-har)
- [Exporting Unsanitized HAR Traces](https://support.pingidentity.com/s/article/Exporting-Unsanitized-HAR-Traces)

看上去还有个命令行参数 `--net-log-capture-mode="IncludeSensitive"` [List of Chromium Command Line Switches « Peter Beverloo](https://peter.sh/experiments/chromium-command-line-switches/#net-log-capture-mode)

## agent-browser 无法访问知乎问题页面

终于用 `--profile` 等方式解决登录状态共享了，发现知乎回答页总是被拦截。开启敏感数据抓包看 Cookie 加调试，核心是无头浏览器计算出来的 `__zse_ck` 无效，替换成真实浏览器算出来的即可（好像会过期）。

在 agent-browser 里就是 
```bash wrap
agent-browser cookies set __zse_ck "005_" --domain .zhihu.com
```

小红书也有类似问题。感觉无头浏览器过不了防爬虫检测，换成有头的试试
