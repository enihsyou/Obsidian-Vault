## MacBook 每隔 10 分钟自动唤醒

#AIGC

结论：触发程序是 `mDNSResponder`。

macOS 内置的 DHCP/mDNS 客户端会反复创建 `MaintenanceWake` 电源断言，断言名 `mDNSResponder:maintenance`，唤醒请求里写明 `info="DHCP lease renewal"`。powerd 据此在 RTC 上设定维护闹钟，睡眠中的机器被拉起约 45 秒完成 DHCP 租约续期，然后重新入睡。

| 证据 | 数据 |
| --- | --- |
| 唤醒原因分布（14 小时日志） | 112 次 DarkWake 中 102 次是 `NUB.SPMI0Sw3IRQ ... rtc/Maintenance`（RTC 维护闹钟）；9 次 `wifibt`；1 次用户活动 |
| 唤醒请求方 | `process=mDNSResponder request=Maintenance`，`info="DHCP lease renewal"`，deltaSecs 稳定在 476–504 秒 |
| 断言与唤醒的对应 | mDNSResponder 创建 `MaintenanceWake` 断言 115 次，与 102 次 `rtc/Maintenance` DarkWake 逐一配对，偏差 0 秒；按小时统计，断言数与唤醒数 1:1（14–23 点每小时 8–11 次） |
| 周期吻合 | 睡眠时长峰值 501/499/502/500/498 秒 ≈ 8.3 分，加 45 秒唤醒 ≈ 9.5 分钟，和你说的“每 10 分钟”对得上 |
| 排除项 | `womp 0`、`networkoversleep 0` 已关；无第三方程序持有唤醒断言；`dasd`（iCloud）有 27 次 SleepService 请求，但只造成零散唤醒 |

说白了就是：路由器的 DHCP 租期偏短，macOS 每 ~9 分钟要续租一次；睡眠中续租必须联网，就只能靠 RTC 闹钟把自己叫醒。

解决方案是去路由器把 DHCP 服务的租约时间改成 86400 秒，因为我之前 [[Diary/2025-11-16#给 Docker 配置完整的 IPv6 macvlan 网络环境]] 让 Docker 容器都接到了局域网中，为了降低 Docker 容器占用一个 IP 地址的时长，把这个时间改成 600 秒，数字对的上。
