## 缩减 PVE LXC 容器引导磁盘大小

```shell
e2fsck -f /dev/pve/vm-103-disk-0
resize2fs /dev/pve/vm-103-disk-0 512M
lvreduce -L 512M /dev/pve/vm-103-disk-0

# or do in oneline fashion
lvreduce --resizefs --size 256M /dev/pve/vm-103-disk-0 
```

如果有问题，比如提示 `WARNING: Thin volume pve/vm-103-disk-1 maps 289013760 while the size is only 268435456.`，最好还是重建

```shell
# 确保容器已停止
pct stop 103

# 将旧的、有问题的卷重命名为备份状态，以防万一
lvrename /dev/pve/vm-103-disk-0 /dev/pve/vm-103-disk-backup

export OLD_DISK=/dev/pve/vm-103-disk-backup
export NEW_DISK=/dev/pve/vm-103-disk-0

# 在 pve/data 这个 thin pool 中创建一个 8GB 的精简卷
lvcreate -V 8G -T pve/data -n $(basename $NEW_DISK)

# 格式化新创建的精简卷
mkfs.ext4 $NEW_DISK

# 创建挂载点
mkdir /mnt/old_lxc
mkdir /mnt/new_lxc

# 挂载旧的备份卷（只读）和新的空白卷
mount -o ro $OLD_DISK /mnt/old_lxc
mount $NEW_DISK /mnt/new_lxc

# 使用 rsync 复制数据
rsync -aHAX --numeric-ids -x --progress /mnt/old_lxc/ /mnt/new_lxc/

# 卸载并清理
umount /mnt/old_lxc
umount /mnt/new_lxc
rmdir /mnt/old_lxc
rmdir /mnt/new_lxc

# 文件系统检查
e2fsck -f $NEW_DISK
```

完成后记得调整 `/etc/pve/lxc/103.conf`

## Rebase on fetched Upstream main

经常在 fork 的仓库把源添加为 upstream remote，现在想要把源的最新变更以 rebase 的形式拉下来

```shell
git pull --rebase upstream main
```
