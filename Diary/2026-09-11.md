## 恢复因意外中断的 SSH Tmux 导致的中断布局混乱

Windows Terminal 在遭遇 SSH 突然掉线时，远端 tmux 来不及发送完整的“退出/恢复终端模式”序列，就可能出现：

- 鼠标突然不能正常框选， tmux 开启的 **VT mouse tracking** 没被关闭
- 输出每换一行就继续往右缩进，换行/光标相关的终端模式停留在异常状态

除了再开一个 Tab 外，运行 ``echo "`ec"`` 即可恢复。

我是封装了一个函数随时调用：

```powershell
# 当 Tmux 意外退出而没有恢复终端状态时，可以硬重置中断状态
function Reset-Terminal {
    [Console]::Write("`ec")
}
```

## VSCode 插件市场的资源无法加载

长久以来，VSCode 插件市场总有些组件无法加载，比如右边的插件信息、网页 Logo 等，表现行为同
- [NET::ERR_CERT_COMMON_NAME_INVALID for domain `vsassetscdn.azure.cn` · 议题 #836 · microsoft/vsmarketplace](https://github.com/microsoft/vsmarketplace/issues/836)

![vsassetscdn CDN 域名无法解析截图](https://github.com/user-attachments/assets/4ac3b816-8679-45d3-aa0b-6e111648482b)

控制台一大堆报错，围绕域名无法解析

```http
GET https://vsassetscdn.azure.cn/v/M279_20260907.3/_content/Header/vs-logo.png net::ERR_NAME_NOT_RESOLVED
```

但开启全局代理后，页面是正常的，注意到访问的域名变成了

```http
GET https://cdn.vsassets.io/v/M279_20260907.3/_content/Header/vs-logo.png
```

分析发起程序，看到是插件页面的 HTML 中硬编码的 URL 两者就有差别，怀疑是根据 IP 做的路由。

解决方法是给插件市场域名单独代理

```ini
# 来源 IP 影响 CDN 域名，中国大陆会分配到无法解析的 vsassetscdn.azure.cn 而不是正常的 cdn.vsassets.io
DOMAIN,marketplace.visualstudio.com
```
