## 检查 context 时发现 firecrawl 工具被强制加载

#AIGC

今天检查 Claude Code 的 context，发现 `mcp__shared__firecrawl__firecrawl_scrape` 和 `mcp__shared__firecrawl__firecrawl_search` 常驻在顶层工具列表里，其他 firecrawl、exa、grafana 工具都躺在 ToolSearch 的延迟列表中，这两个工具等于每轮都占着 prompt。

机制是这样的：Claude Code 开启 Tool Search 后，MCP 工具默认都延迟加载，但服务器可以在 `tools/list` 里给单个工具加 `_meta: {"anthropic/alwaysLoad": true}`，客户端会无视延迟机制直接把它放进 prompt。Firecrawl 的 `firecrawl_scrape` 和 `firecrawl_search` 就带这个标记，MCPJungle 作为代理原样透传 `_meta`，标记就到了客户端。

客户端侧有个服务器级开关能压过工具级标记：服务器配置里的 `alwaysLoad: false` 让该服务器的所有工具都走延迟加载，`true` 则是全部常驻。

处理方式是在 Claude Code 的用户配置 `~/.claude.json` 里，给 `mcpServers.shared` 加一个字段：

```json
"shared": {
  "type": "http",
  "url": "http://mcpjungle.docker/mcp",
  "alwaysLoad": false,
  "headers": { "Authorization": "Bearer ..." }
}
```

改完用 `claude mcp get shared` 确认配置仍能正常解析和连接。
