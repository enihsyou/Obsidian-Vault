## 在 PVE 用 LXC 安装 OpenWrt

- [PVE8.3.1 LXC下安装 OpenWRT 记录 - airoot - 博客园](https://www.cnblogs.com/airoot/p/18715211) 参考，但是没必要那么复杂
- [[OpenWrt Wiki] OpenWrt in LXC containers](https://openwrt.org/docs/guide-user/virtualization/lxc#via_rootfs_extraction)

访问符合自己架构的下载页面选个最新 OpenWrt 版本。（也可以从速度更快的 [Linux Containers - Image server](https://images.linuxcontainers.org/images/openwrt/24.10/amd64/default/) 下载）

在 [Linux Containers - Image server](https://images.linuxcontainers.org/) 找到符合自己架构的 OpenWrt 版本，比如我需要去 [Index of /images/openwrt/24.10/amd64/default/](https://images.linuxcontainers.org/images/openwrt/24.10/amd64/default/) 中选个最新的日期。

> 注意不要使用 [downloads.openwrt.org](https://downloads.openwrt.org/releases/24.10.4/targets/x86/64/) 的下载源，一定要用的话，请按照 [[2025-10-27#LXC 安装的 OpenWrt 在安装 dnsmasq-full 后无法启动 dnsmasq]] 的说明，安装后修改系统文件。

里面会有多个文件，这里下载 LXC 支持的 `rootfs.tar.xz` 就好。不要选择 .img.gz 结尾的 _ 镜像 _ 文件，那个是给虚拟机用的。

接下来就是创建 LXC 了，按需调整参数，选择镜像文件

```shell wrap
pct create 104 \
  --description "Router for PVE subnet" \
  --hostname openwrt --net0 name=eth0,bridge=vmbr0,ip=dhcp,ip6=auto --net1 name=eth1,bridge=vmbr1,ip=dhcp,ip6=auto \
  --rootfs local-lvm:0.5 --arch amd64 --cores 1 --memory 512 \
  --ostype unmanaged --arch amd64 /var/lib/vz/template/cache/openwrt-24.10.4-x86-64-rootfs.tar.gz

echo "lxc.include: /usr/share/lxc/config/openwrt.common.conf" >> /etc/pve/lxc/104.conf

pct start 104
```

因为我的网络设置是计划让 OpenWrt 服务所有其他 VM 所在的子网：
- `vmbr0 - eth0 - wan 192.168.9.0/24` 上游连接 PVE 所在的主机网络
- `vmbr1 - eth1 - lan 192.168.2.0/24` 下游连接 LXC 其他容器的虚拟网络

所以会需要从 WAN 口访问 LuCI 管理页面，得添加个防火墙配置。
- [Access LuCl via WAN : r/openwrt](https://www.reddit.com/r/openwrt/comments/iehbre/access_lucl_via_wan/)
- [[OpenWrt Wiki] Accessing LuCI web interface securely](https://openwrt.org/docs/guide-user/luci/luci.secure#allow_access_from_internet)

```shell
# start a shell in lxc
pct enter 104

# create a new section of the rule in /etc/config/firewall
# allow http connection from WAN side
uci add firewall wan_https_allow
uci set firewall.wan_https_allow=rule
uci set firewall.wan_https_allow.name='Allow HTTP, HTTPS from WAN'
uci set firewall.wan_https_allow.src='wan'
uci set firewall.wan_https_allow.proto='tcp'
uci set firewall.wan_https_allow.dest_port='80 443'
uci set firewall.wan_https_allow.target='ACCEPT'

# allow ssh connection from WAN side
uci add firewall wan_ssh_allow
uci set firewall.wan_ssh_allow=rule
uci set firewall.wan_ssh_allow.name='Allow SSH from WAN'
uci set firewall.wan_ssh_allow.src='wan'
uci set firewall.wan_ssh_allow.proto='tcp'
uci set firewall.wan_ssh_allow.dest_port='22'
uci set firewall.wan_ssh_allow.target='ACCEPT'

# save the new section to /etc/config/firewall
uci commit firewall
# reload the firewall to pick up the new rule
/etc/init.d/firewall reload
```

## LXC 中的 uptime 和 free 返回主机的信息

#有路难走

比如主机有 64GiB 内存，分配给 LXC 有 0.5 GiB，但在 `free` 中输出的是主机信息，没有读取容器应用的设置。Uptime 也是同理，显示主机的启动时间。

```console
$ head -n3 /proc/meminfo  
MemTotal: 65536 kB  
MemFree: 2052 kB  
MemAvailable: 47149 kB  

$ free
total        used        free      shared  buff/cache   available
Mem:       65725628     2303211    63027148       37312      395269       47145
Swap:      33554428           0    33554428
```

- [Incorrect results with uptime and free for alpine containers - Incus - Linux Containers Forum](https://discuss.linuxcontainers.org/t/incorrect-results-with-uptime-and-free-for-alpine-containers/22424) 也有人遇到过，不过没解决
- [System call interception - Incus documentation](https://linuxcontainers.org/incus/docs/main/syscall-interception/#sysinfo) 在 Incus 有 [实现](https://github.com/lxc/incus/blob/9944ea686d62da3f158f0c4efa28285b8bb0a78b/internal/server/seccomp/seccomp.go#L1748)，但 PVE 用的是 LXC
- [LXC 5 load averages are wrong in Debian 12 container · 议题 #4372 · lxc/lxc](https://github.com/lxc/lxc/issues/4372#issuecomment-2041127257) 给出了无奈的解决方向

受影响的有 Alpine 和 OpenWrt 实例，Ubuntu 没问题。因为它们俩用 `sysinfo` 系统调用来读取信息，而这部分不能被 LXCFS 重写。

## Edge 新标签页变成 `ntp.msn.cn/edge/ntp`

我目前的习惯是，想要 Google 搜索什么的时候，按 <kbd>Ctrl+T</kbd> 打开新标签页，开始在地址栏上键入关键字，按回车进行搜索。

> 其实更应该用 SurfingKeys 的 `sg` 指令，快速用 Google 搜索剪贴板文字

可近期 Edge 新标签页一打开，会有短暂的一秒空白页，然后才跳转到真正的「新标签页面」。而这个跳转，会把地址栏上的内容清空掉 😠。经常就盲打途中发现之前输入的内容没了，要么清空再打一遍，要么重置光标再去补全，反正体验很差劲。

我通过开发者工具发现，打开空白新标签页的实际路径是这样的：
1. `edge://newtab` 元链接，指示浏览器打开新选项卡页面
2. `https://ntp.msn.com/edge/ntp?locale=zh-CN&title=新建标签页&dsp=1&sp=Bing&feed_dis=off&en_widget_reg=false&PC=U531&adppc=EDGEESS`
   第一次 302 跳转，sp 参数对应在 [隐私、搜索和服务 / 搜索和连接体验 / 地址栏和搜索 / 在地址栏中使用的搜索引擎](edge://settings/privacy/services/search) 设置的搜索引擎
3. 如果是 Bing，并且地理位置信息在中国大陆，会再次跳转到 `ntp.msn.cn` 的相同地址，打开一个满是 MSN 广告的「个性化主页」，和 Windows 11 左下角任务栏小组件差不多。打开「MSN 智能探索 / MSN Copilot Discover」能好一些，但跳转的加载速度真的是慢。
4. 如果是其他地区，会是国际版的 `ntp.msn.com`
5. 如果是其他搜索引擎，或者网络「不好」，比如我在 [[2025-08-10#无法修改 Edge 浏览器搜索引擎地址中的地区信息]] 改成了 Google HK，则会来到比较干净的 `chrome-search://local-ntp/local-ntp.html`。可以按照 [[2025-09-04#修改 Edge 的 New Tab Page 的最常访问网站]] 的方式修改常用网站链接。

现在我的需求就是，干净简洁，别瞎几把跳转，禁止中国大陆广告。

选择通过组策略直接修改新标签页为 `chrome-search://local-ntp/local-ntp.html`，修改的位置在 `本子组策略编辑器 > 用户配置 > 管理模板 > Microsoft Edge > 启动、主页和新标签页 > 配置新的标签页 URL`。这样就跳过了从互联网网页跳转的过程，省去建立网络链接等动作产生的等待白屏。

想法很美好，可现在的版本 140.0.3485.54，会提示「此策略被阻止，其值将被忽略。」，因为这个策略只在「受组管理的设备」上可用 😠，我都无法理解为什么微软会有这种限制，就这么想推广自己的 NewTab？

## OpenWrt IPv6 Passthrough

#OpenWrt #IPv6

有的地方也叫 relay 模式

- [二级路由(openwrt)开启ipv6中继(ipv4和ipv6共存) – late哥哥笔记](https://www.lategege.com/?p=676)
- [二级路由下的Openwrt获取ipv6 – 沧水的博客](https://cangshui.net/4730.html)
- [OpenWRT 路由器IPv6实战配置长篇教程：纠正你的IPv4思维！__什么值得买](https://post.smzdm.com/p/awzodmpp/)
- [【全网最细】ipv6工作流程详解，openwrt软路由配置ipv6教程，homeproxy、openclash代理ipv6流程，sing-box、mihomo，ipv6科学上网不冲突，ipv6代理](https://www.youtube.com/watch?v=klQ6JbZEeJ0)

Version: `OpenWrt 24.10.2 r28739-d9340319c6 / LuCI openwrt-24.10 branch 25.168.50434~d6b13f6`

1. WAN 接口 DHCP 服务器指定为主接口，至少开启 RA 中继，才能在 LAN 侧获得地址
2. WAN6 接口，如果有大于/64 的地址块，勾上扩展前缀，获取 IPv6-PD 地址块，才能在 LAN 侧用 SLAAC 取得地址
3. LAN 接口 DHCP 服务器开启中继模式；IPv6 分配长度 64；IPv6 后缀填 eui64，避免分配到 `::1`
4. LAN6 接口可选，不一定要在 LAN 侧添加 DHCPv6 客户端

```nginx title="/etc/config/network"
config interface 'wan'
        option proto 'dhcp'
        option device 'eth0'

config interface 'wan6'
        option proto 'dhcpv6'
        option device 'eth0'
        option reqaddress 'try'
        option reqprefix 'auto'
        option norelease '1'
        option extendprefix '1'

config interface 'lan'
        option proto 'static'
        option device 'br0'
        option ipaddr '192.168.2.1'
        option netmask '255.255.255.0'
        option ip6ifaceid 'eui64'
        option ip6assign '64'

config device
        option type 'bridge'
        option name 'br0'
        list ports 'eth1'
```

```nginx title=/etc/config/dhcp
config dhcp 'lan'
        option interface 'lan'
        option start '10'
        option limit '100'
        option leasetime '12h'
        option dhcpv4 'server'
        option ra 'relay'
        option dhcpv6 'relay'
        option ndp 'relay'

config dhcp 'wan'
        option interface 'wan'
        option ignore '1'

config dhcp 'wan6'
	    option interface 'wan'
	    option ra 'relay'
	    option ndp 'relay'
	    option dhcpv6 'relay'
	    option master '1'
```
