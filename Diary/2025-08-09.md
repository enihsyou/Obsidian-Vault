## HTTPie 启动耗时太慢

```powershell
$ Measure-Command { http --version } | % TotalSeconds
0.5114763  
$ Measure-Command { xh --version } | % TotalSeconds
0.0157881
$ Measure-Command { curl --version } | % TotalSeconds
0.0131859
```

估计是 import 链拖了后退

HTTPie/cli 最近的版本还是去年的 3.2.4 ，并且 13 年前的对 IPv6 only 支持的需求 [Add -4 and -6 switches to force IP protocol version · Issue #94 · httpie/cli](https://github.com/httpie/cli/issues/94) 到现在都没加上，换成 [ducaale/xh: Friendly and fast tool for sending HTTP requests](https://github.com/ducaale/xh) Rust 版了。

然后为了避免肌肉记忆再回到旧版本，添加个软链接

```powershell
uv tool uninstall httpie
Set-Alias -Name http -Value xh -Description "a Rust version of HTTPie"
```

## Merlin Clash 的 TProxy IPTables 影响局域网内跨子网访问

在开启了 Merlin Clash + Tproxy mode 的路由器上挂了一个与路由器同网段的 192.168.9.17 设备，上面运行了处在 192.168.2.0/24 网段的虚拟机，并且设备当做路由器处理转发。奇怪的是两个网段可以 ping 通但是无法建立 TCP 连接。

`2025-09-26` 在 192.168.9.201 上配置一个子网为 192.168.5.0/24 routed 模式的 Docker Bridge，宿主机和容器正常访问，但局域网内其他设备能 PING 通容器，无法建立 TCP 连接。实测是相同问题

现象有了，那么为什么来自局域网另一网段的流量会走到 Tproxy 去呢，

这里从设备上发了个内网请求，在路由器上抓包，在路由器上一见到链接就是 ESTABLISHED 状态，而不是 NEW ，所以进入了 INVALID state。

```shell
# conntrack -E | grep 192.168.2.82
    [NEW] tcp      6 300 ESTABLISHED src=192.168.9.18 dst=192.168.2.82 sport=8126 dport=39490 [UNREPLIED] src=192.168.2.82 dst=192.168.9.18 sport=39490 dport=8126
 [UPDATE] tcp      6 120 FIN_WAIT    src=192.168.9.18 dst=192.168.2.82 sport=8126 dport=39490 [UNREPLIED] src=192.168.2.82 dst=192.168.9.18 sport=39490 dport=8126
 [UPDATE] tcp      6 60  CLOSE_WAIT  src=192.168.9.18 dst=192.168.2.82 sport=8126 dport=39490 [UNREPLIED] src=192.168.2.82 dst=192.168.9.18 sport=39490 dport=8126
```

怀疑是 A(192.168.9.18) to B(192.168.2.82) 跨网段经路由器路由，B to A 直接链路直连不经过路由器导致的这个现象。
难以关闭路由器的硬件加速，手上也没有可用的交换机，也就难以抓到 LAN 设备间的流量来验证。
不过通过在 192.168.9.18 上添加一条 192.168.2.82/32 的静态路由，也是能通的说明确实出在路由器上。

> 另外有可能是 NAT 没配置好？暂时没去验证
> [Linux 2.4 NAT HOWTO: Destination NAT Onto the Same Network](https://www.netfilter.org/documentation/HOWTO/NAT-HOWTO-10.html)

那么有几个解决思路
1. 让 192.168.9.17 做 NAT，对外屏蔽子网信息，相当于同一子网间设备互访
当然能不 NAT 就不 NAT

```shell title="在 192.168.9.17 上设置防火墙规则"
iptables -t nat -A POSTROUTING -s 192.168.2.0/24 -o vmbr0 -j MASQUERADE
```

2. 路由器防火墙不要丢弃本地子网之间的流量
也就是把 DROP 指令删掉。但指令是 Merlin Clash 加的，要改它脚本，每次更新都得做一遍。

```shell title="删除 DROP 规则"
iptables -t mangle -D merlinclash_divert -m conntrack --ctstate INVALID -j DROP
```

> [工欲善其事，必先利其器 —— 我的家庭网络组网方案 | Sukka's Blog](https://blog.skk.moe/post/home-network-setup/#%E9%98%BB%E6%AD%A2-Invalid-%E7%8A%B6%E6%80%81%E7%9A%84%E6%95%B0%E6%8D%AE%E5%8C%85%E6%B3%84%E6%BC%8F%E5%88%B0%E4%BA%92%E8%81%94%E7%BD%91) 这里也提到了 CONNTRACK DROP 的关键字，难道丢弃 Invalid 是某种最佳实践？

3. **提前绕过透明代理，本地流量不 mangle**「目前选择」
只需要修改主路由一处，绕过 dest 方向流量足够

```shell title="流量绕行"
iptables -t mangle -I PREROUTING -d 192.168.2.0/24 -j RETURN
```

问题是怎么把这段添加进防火墙规则，好在手动新增的规则并且不会被 MerlinClash 删除，那就考虑路由器脚本。刚好之前留了个位置 [dotfiles/system/router/RT-AX86U/N200enihsyou.sh at Windows · enihsyou/dotfiles](https://github.com/enihsyou/dotfiles/blob/Windows/system/router/RT-AX86U/N200enihsyou.sh)，加在最后就行

4. 让 192.168.2.82 访问 192.168.9.18 也经过路由器转发，在 conntrack 表上留下记录
多绕个圈子，感觉非常蠢。我也不知道怎么实现

5. 让 192.168.2.82 访问 192.168.9.18 不经过路由器转发，添加静态路由
只需要修改虚拟机的宿主机一处。但适用场景有限

```shell title="添加静态路由"
# on 192.168.9.17 (supervisor of 192.168.2.82)
ip route add 192.168.2.0/24 via 192.168.9.17 dev vmbr0
```
