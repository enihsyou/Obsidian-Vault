## 捕获启动 bash 时的调试输出

也就是把 `bash -x` 的输出重定向到文件中。目的是跟踪 WSL2 Ubuntu 启动慢的问题。

为了避免当前 Shell 的影响，我打算从 `bash --norc` 开始。
因为在 PowerShell 中使用 `ubuntu run bash -x > trace.txt` 获得不到输出，只好这样：
- [profile - Find out what scripts are being run by bash at login - Unix & Linux Stack Exchange](https://unix.stackexchange.com/questions/334382/find-out-what-scripts-are-being-run-by-bash-at-login/631291#631291)
- [profiling - How can I profile a Bash shell script slow startup? - Stack Overflow](https://stackoverflow.com/questions/5014823/how-can-i-profile-a-bash-shell-script-slow-startup/5015179#5015179)

```shell
# start WSL2 from PowerShell
ubuntu run bash --norc
# inside WSL2 bash
exec 3> trace.txt
export PS4='+ $EPOCHREALTIME\011 '  
export BASH_XTRACEFD=3
/bin/bash -lixc exit
```

但主要还是想看到每行执行时间，好在有人已经做好介绍了
- [profiling - How can I profile a Bash shell script slow startup? - Stack Overflow](https://stackoverflow.com/questions/5014823/how-can-i-profile-a-bash-shell-script-slow-startup/20855353#20855353)
多种方法，最后我选第一种，再修改一下脚本让 diff 展示更直观

```shell
# inside WSL2 bash
exec 3>&2 2> >(tee sample-time.log | sed -u 's/^.*$/now/' | date -f - +%s.%N >sample-time.tim)
bash -lixc exit

# exit bash and reopen
^D

# then display result
paste <(
    while read tim ;do
	    [ -z "$last" ] && last=${tim//.} && first=${tim//.}
        crt=000000000$((${tim//.}-10#0$last))
        printf "%12.9f\n" ${crt:0:${#crt}-9}.${crt:${#crt}-9}
        last=${tim//.}
    done < sample-time.tim
) <(echo;cat sample-time.log) > sample-time.txt

# sort to get significent
sort -k1 -n -r sample-time.txt | head
```
