之前 [[Diary/2025-09-05#MSYS2 的 rsync 上传到 Synology 报错]] 出现过相似的报错信息，不过那次是无权限，因为 Synology 的 rsync 没有启用。这次的错误是 SSH 运行错误。

实际上原因是这里的 `ssh` 解析到 Windows 的版本

```console
$ which ssh
C:/Program Files/OpenSSH/ssh.exe
```

而 MSYS2 的 rsync 期望 `/usr/bin/ssh` / `C:/msys64/usr/bin/ssh.exe` 的。所以解决思路就是添加 `-e /usr/bin/ssh`。

还有个一劳永逸但别扭的办法 `$env:PATH = "/usr/bin/;" + $env:PATH`
或者把 `C:\msys64\usr\bin` 加到系统环境变量 PATH 中。

破坏性都有点大，我还是 `-e` 吧

## 管理私密环境变量的方法

1. OpenRC
- [The Magic of conf.d · OpenRC/openrc](https://github.com/OpenRC/openrc/blob/master/user-guide.md#the-magic-of-confd)

```shell title="/etc/conf.d/service"
export DB_HOST=127.0.0.1
```

2. SystemD
- [Using environment variables in systemd units | Flatcar Container Linux](https://www.flatcar.org/docs/latest/setup/systemd/environment-variables/)

```systemd title="/etc/systemd/system/myservice.service.d/override.conf"
[Service]
Environment="DB_HOST=127.0.0.1"
EnvironmentFile=-/etc/sysconfig/httpd
```

3. Taskfile
- [Add support for interpolation in dotenv: | Task](https://taskfile.dev/docs/changelog#v3-5-0-2021-07-04)

```yaml
dotenv: ['.env']
tasks:
  default:
    cmds:
      - echo $DB_HOST
```

4. Docker Compose
- [Set environment variables within your container's environment | Docker Docs](https://docs.docker.com/compose/how-tos/environment-variables/set-environment-variables/)

与 docker-compose.yaml 同目录的 `.env` 文件

```yaml title=docker-compose.yml
services:
  webapp:
    environment:
      DB_HOST: "${DB_HOST}"
```

## 执行带 PTY 的 SSH 命令

另外如果想要带 PTY，得这样 `ssh -tt pve lxc-attach -n 106 -- ls`。
因为 Heredoc 对付带有 exec 的目标命令 `pct exec 100 -- ls`， `lxc-attach -n 100 -- ls` 会卡住无法返回。一种方法是在命令里关闭 stdin `lxc-attach -n 100 -- ls < /dev/null`，但不稳定

最终一行的比较稳定

```shell
ssh -ttq pve pct exec 106 -- rc-service caddy reload
```
