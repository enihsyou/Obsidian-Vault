## 使用 MACVLAN 为主机同时分配静态 IP 并取得动态 IP

有了之前 [[2025-11-07#节点 hostname 变更后 /etc/pve 目录清空]] 的 [[2025-11-16#PVE 目录又一次没了]] 的经验，管理端口不设置静态地址还是比较危险的。
但我还是想 [[2025-11-07#让 DNSmasq 响应 DHCPv4 主机的 IPv6 地址]]，有个好主意，让主机网卡拥有多个 IP 地址。

1. 一张网卡两个 IP
也就是 IP alias 技术，或者叫 secondary IP，挺常用的，在 [[RG-MA3063 开启 SSH#通过网络连接到设备]] 也记录过。

2. 两张网卡两个 IP
好处是可以用不同的 MAC 地址，在 DHCP 时能获得与静态不同的 IP。

```txt title="/etc/network/interfaces"
auto enp5s0
iface enp5s0 inet manual
#Qualcomm Atheros Killer E2500 Gigabit Ethernet Controller

auto vmbr0
# 这里静态地址已经在 DHCP 上注册过了，重复一遍是为了在 DHCP 上产生解析记录
iface vmbr0 inet dhcp
iface vmbr0 inet static
        address 192.168.9.17/24
        bridge-ports enp5s0
        bridge-stp off
        bridge-fd 0
# 获得 SLAAC 地址
iface vmbr0 inet6 auto

# 通过 DHCP 获得一个地址
auto mgmt
iface mgmt inet dhcp
        pre-up ip link add link vmbr0 name mgmt type macvlan mode bridge
        post-down ip link del mgmt
# 获得 SLAAC 地址
iface mgmt inet6 auto
```

对于使用 systemd-networkd 的可以参考这里 [Configuring a second static IP with its own MAC address on an existing interface - ArchWiki](https://wiki.archlinux.org/title/Systemd-networkd#Configuring_a_second_static_IP_with_its_own_MAC_address_on_an_existing_interface)
## 使用 SLAAC 获得长短两个 IPv6 地址

在配置了 IPv6 SLAAC 的环境里，比如 [[2025-09-08#OpenWrt IPv6 Passthrough]]，我发现在启用 `accept_ra` 的基础上，再设置 `inet6 auto` 可以多获得个短地址。,

```txt {"取得 DHCP 地址": 2} {"取得 SLAAC 长地址": 4} {"取得 SLAAC 短地址": 6}
auto vmbr0

iface vmbr0 inet dhcp

        post-up sysctl net.ipv6.conf.vmbr0.accept_ra=2

iface vmbr0 inet6 auto
```

`accept_ra` 设置为 1 或者 2 都行，这里设置为 2 是要在开启 ip_forward 的基础上也获得 SLAAC 地址

## OpenWrt 支持注册 IPv6 解析

之前在 ASUS Merlin 固件上搞了 [[2025-11-07#让 DNSmasq 响应 DHCPv4 主机的 IPv6 地址]]，其实就是加一行 `dhcp-range=::,constructor:br0,ra-names` 配置。但在 OpenWrt 上 dnsmasq.conf 是由 `/etc/config/dhcp` 生成的，那么得有个地方添加这个属性。

找遍了也没有比较直观的地方可以进行这个配置，那么诉诸自定义配置肯定可以。好在虽然文档上没有，[Add Dnsmasq Custom Options field in LuCi GUI - For Developers - OpenWrt Forum](https://forum.openwrt.org/t/add-dnsmasq-custom-options-field-in-luci-gui/193184/18) 新增的 extraconftext 能承载任意文本。

```shell
uci set dhcp.@dnsmasq[0].extraconftext='dhcp-range=::,constructor:br0,ra-names'
uci commit dhcp
/etc/init.d/dnsmasq restart
```

不过光是 OpenWrt 支持这个属性还不够，得安装的 DNSmasq 支持 DHCPv6 才行，比如当前我的版本是这样，说明不支持

```shellsession del="no-DHCPv6" wrap
# dnsmasq --version
```

而支持 ra-names 这套操作的主路由上版本是带 DHCPv6 的 2.91

```shellsession add="DHCPv6" wrap
# dnsmasq --version

Compile time options: IPv6 GNU-getopt no-RTC no-DBus no-UBus no-i18n no-IDN DHCP DHCPv6 no-Lua TFTP no-conntrack ipset no-nftset no-auth DNSSEC no-ID loop-detect no-inotify no-dumpfile
```

安装倒是简单，`opkg install dnsmasq-dhcpv6 --force-overwrite`，强制动作是用来移除旧的版本。然后按照 [[2025-10-27#LXC 安装的 OpenWrt 在安装 dnsmasq-full 后无法启动 dnsmasq]] 的修正方式调整启动脚本。

记得按 [[2025-09-08#OpenWrt IPv6 Passthrough]] 设置好 Passthrough 模式。
